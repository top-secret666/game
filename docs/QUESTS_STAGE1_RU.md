# Квест-лист Stage 1 (Монолит)

Ниже — короткие квесты, каждый даёт 1–2 навыка и двигает проект.

## Параллельная ветка (для атмосферы, но с пользой для кода)
### Quest A — «Витражная клиника» (арт + данные)
**Цель:** зафиксировать локации/предметы/улучшения так, чтобы они стали доменными сущностями.
- Описать 5 локаций и 10 объектов среды (включая растения) как справочник.
- Связать улучшения (тихая комната/оранжерея) с кейсами через `WardUpgrade`.

## Quest 0 — «Кодекс Гильдии» (Git)
**Цель:** репозиторий + базовая дисциплина.
- `main` защищаем правилами (позже), работаем через ветки.
- `.gitignore` для IDE/сборки.
- README: как запустить.

## Quest 1 — «Очаг Проекта» (Spring Boot + Postgres + Flyway)
**Цель:** приложение стартует, миграции накатываются.
- Spring Web, Validation, Spring Data JPA, PostgreSQL, Flyway.
- `application.yml` для локального профиля.
- Миграция `V1__init.sql`.

## Quest 2 — «Игрок Гильдии» (Player MVP)
**Цель:** игрок может зарегистрироваться и получить профиль.
- `POST /api/players`
- `GET /api/players/{id}`
- DTO + валидация.

## Quest 3 — «Кейс приёма» (Case MVP)
**Цель:** создать и читать кейс.
- `POST /api/cases`
- `GET /api/cases/{id}`
- Статусы: DRAFT/FINAL.

## Quest 4 — «Заметка смены» (SessionNote)
**Цель:** сохранять заметку разговора.
- `POST /api/cases/{id}/notes`
- Версионирование (опционально, но полезно).

## Quest 5 — «Бланки» (FormAnswer)
**Цель:** ответы анкеты как ключ-значение.
- `PUT /api/cases/{id}/form`
- Схема ключей фиксирована справочником (позже кешируем).

## Quest 6 — «План поддержки» (SupportPlan)
**Цель:** план с целями и условиями среды.
- `PUT /api/cases/{id}/plan`
- Актуальная версия плана — одна.

## Quest 7 — «Проверка начальства» (AuditCheck)
**Цель:** отправить кейс на проверку и получить результат.
- `POST /api/cases/{id}/submit`
- `GET /api/cases/{id}/audit`
- Пока проверка может быть синхронной (позже сделаем события/очередь).

## Definition of Done (для каждого квеста)
- Контракт API (DTO) понятен.
- Ошибки валидации возвращаются аккуратно.
- Сущности не текут наружу (не отдаём JPA entity прямо в JSON).
- Миграции обновлены.
